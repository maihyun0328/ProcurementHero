# v3 내일을 준비하는 수첩 (2026-11-06~07, 4차 구현)

> 가상의 2038년 조달청 지역 현장 담당자와 AI 수첩 '내일'은 창작 설정입니다. 조달청의 공식 사업·미래 계획·계약 절차가 아닙니다. '내일'의 예측은 미션 데이터의 정해진 문장이며 실제 AI가 분석하지 않습니다.

v2의 이동·관찰·수첩·별 규칙을 그대로 쓰고, **계획과 실제 결과 사이에 시간 경과와 상황 발생을 넣었습니다.** 아래 v2 절의 '설치하면 바로 해결' 설명은 이 절이 대체합니다.

## 판정과 연출의 분리

- 승인 = `FieldRules.Evaluate` 스냅샷 고정. 수첩 미리보기·시설 대응·별·엔딩 모두 이 판정의 `Solved`만 씁니다.
- `FieldWorld` 표시값: `level`(판정상 해결 0/1) · `hazard`(상황 0~1) · `respond`(대응 0~1). 해결 모습 = `level × respond`, 문제 세기 = `lerp(earlyLevel, 1, hazard)`.
- 시나리오 시간(현장 시간, 일시정지 시 정지): 시간 경과 2.0초 → 상황 0.6초 → 대응 0.9초 → 정착 1.4초.
- 침수: 물높이 = 세기 × (1 − 대응). 모래주머니로 해결한 곳은 처음 물높이(earlyLevel)에서 더 오르지 않음. 물높이 0.5 초과일 때만 웅덩이 충돌.
- 전력: 상황 전엔 평소 전기로 켜짐, hazard 0.5 이상이면 정전, 대응하면 해결한 곳만 다시 켜짐.
- 어둠: 저녁 하늘빛이 현장 전체를 덮고, 해결 구역만 빛. 보행등은 사람이 가까울 때 더 밝음(판정 무관).
- 더위: 주민이 옮겨 가는 해결(그늘막·현관 대형 냉방기)은 그 자리만 나아짐. 현관 냉방은 현관 앞 반실외 자리에만 냉기·바람.

## AI 도움 (2·3현장, 필수 관찰 뒤)

1. **AI 단서** `FieldRules.Hint(spec, plan, observed)`: 관찰한 필수 문제 중 빠진 대비 → 같은 문제에 겹친 효과 → 관찰한 곳에 닿지 않는 물품 → 예산 초과 → 관찰한 추가 목표 → 모두 갖춤 중 **하나**. 관찰하지 않은 문제, 놓을 자리·물품은 말하지 않고 계획을 바꾸지 않습니다.
2. **배치안까지 보기**(단서 창에서 직접 선택): `FieldRules.Recommend(spec, observed)` — 예산 안의 모든 계획을 (관찰한 필수 해결 수, 관찰한 추가 해결 수) 큰 순 → 비용 작은 순 → 물품 수 작은 순. 지금 계획과 예산·대비를 비교해 보여 주고, '이 계획 적용'을 눌러야 편집 계획에 들어갑니다. 승인·공급은 하지 않고 별에도 영향이 없습니다.

## 장식용 이용객

`crowd`(머무는 자리)와 필요한 사람에게만 `crowdRoutes`(출발 → 대기 지점 → 경유점 → 목적지, 필요한 문제 ID). 상황 진행만큼 대기 지점까지 오고, 필요한 문제가 확정 판정상 해결되고 지금 지나갈 수 있는 상태(침수는 깊은 물이 빠진 뒤)일 때만 일정한 걸음(초당 4.6)으로 목적지로 갑니다. 대피소 주민은 정문 진입로(R)가 해결돼야 진입로를 지납니다.

## 관찰 진행도와 필수 관찰

HUD '관찰 n/전체'는 추가 대상을 포함한 모든 관찰 대상(미션 데이터의 문제 수), 아랫줄 '필수 n/m'은 승인 조건인 필수 관찰. 승인은 필수 관찰만 요구한다.

## 시작 연출

앱 실행당 한 번, 약 4.8초: 닫힌 수첩(조명, 0~0.9) → AI '내일' 알림(0.9~3.9, 알림음 1회) → 수첩이 펼쳐지며 새봄시 지도·예상 위험(1.9~3.0) → 수첩이 커지며 빠짐(3.3~4.1) → 타이틀 카드 등장(3.9~4.8). 타이틀 배경은 시작 때 어두운 화면 뒤에 미리 만들고, 배경음은 1.5초 동안 서서히 켜짐. Space·Enter·Esc·버튼으로 건너뛰며, 정상 재생과 같은 타이틀 상태로 끝나고 메뉴는 다음 프레임부터 눌림. 포커스를 잃으면 멈춤. 저장·timeScale 변경 없음.

## 침수: 얕은 물과 깊은 물

| 단계 | 얕은 물(문제 구역) | 깊은 물(Puddle 장애물) |
|---|---|---|
| 상황 전 | 옅은 하늘색, 통행 가능 | 없음(그림·충돌 모두) |
| 강우 증가(물높이 > 0.5) | 넓게 퍼짐 | 진한 파랑·테두리·주의 표지 + 같은 사각형 충돌 |
| 배수펌프 대응 후 | 젖은 바닥 자국 | 없음, 통로 다시 열림 |
| 모래주머니 | 강우 중에는 처음의 얕은 물에서 더 오르지 않고, 대응이 끝나면 젖은 바닥 자국만 남음 | 생기지 않음 |

상황 시작 때 깊어질 물 안·가장자리의 담당자는 가장 가까운 물 밖으로 걸어 나가고, 바로 적용한 상태도 같은 규칙. 이용객은 깊은 물이 빠진 뒤에만 지나감.

## 완주 뒤 현장 선택·재도전

세 현장을 모두 성공한 저장에서 타이틀·엔딩 최종 화면 → '현장 선택' → 카드 '재도전'. 고른 현장만 처음 상태로 하고 결과는 그 시도 그대로 보여 줌. 대표 결과는 성공이면서 별이 같거나 많을 때만 그 시도로 통째로 교체(`FieldProgress.SubmitRetry`), 합계·엔딩은 대표 결과로 다시 계산. 결과 화면: 같은 현장 다시 · 현장 선택 · 타이틀로.

## 수첩 정보 구조

기본: 물품(그림·이름·특징·닿는 곳·비용·체크), 계획 칸, 예산·확정 불가 이유(늘 보임). 관찰 기록 카드는 이름 + 핵심 단서(`clue`) 한 줄, '자세히'(클릭·Enter, 닫기·Esc)에 전체 메모·필수 여부·주민 말. 배치안은 지점별 물품 + 예산·대비 수 비교, 고르는 방식은 '설명' 버튼.

## 엔딩

현장별 최종 결과를 상황 뒤 모습으로 3.2초씩 → 수첩 마지막 체크와 "AI는 내일을 예측하고, 우리는 현장을 확인해 필요한 선택을 합니다." → "내일의 불편을 줄이는 오늘의 조달." → 최종 별 화면.

# v2 현장 수첩 버전 (2026-11-06 구현)

씬 `Assets/ProcurementHero/Scenes/FieldNotebook.unity` · 데이터 `Assets/ProcurementHero/Data/Field/` · 규칙 `Scripts/Core/Field/FieldRules.cs`

## 흐름

타이틀 → 현장 도착(차가 서고 담당자가 내려 둘러봄 · 말풍선 한 줄) → 탐색과 관찰 → 수첩 계획 → 계획 확정 → 배송과 설치 → 현장 재확인 → 별 평가 → 다음 현장 → 엔딩

|---|---|---|
| 도착 | Space·Enter·E·현장 클릭·버튼으로 건너뛰기, Esc 일시정지 | 첫 도착 약 4.3초, 이미 본 현장·2번째 현장부터 약 2.6초, 재계획은 도착 없이 바로 수첩 |

| 수첩 | 방향키·WASD로 항목 이동, Enter 실행, Tab·Esc 닫기 | 현장 이동과 연출 정지, 계획·선택 지점 유지 |
| 설치 | Space·버튼으로 건너뛰기, Esc 일시정지 | 건너뛰어도 같은 최종 상태를 한 번만 적용 |

- 상태가 바뀐 프레임에는 현장 입력을 받지 않아, 한 번 누른 키가 두 동작을 일으키지 않습니다.
- 일시정지는 `Time.timeScale = 0`, 닫으면 1로 복구. 일시정지 위에 설정 창을 겹쳐 열고 닫아도 정지가 남지 않습니다.

## 관찰

- 관찰 범위 2.2 안에서 가장 가까운 대상 하나만 고릅니다. 멀리서 클릭하면 "더 가까이 가야 살펴볼 수 있어요".
- 관찰 연출은 한 줄로 이어집니다: 담당자가 몸을 숙여 살핌 → 주민이 반응(말풍선) → 문제 그림이 수첩 버튼으로 날아감 → 도착하는 순간 관찰 수가 오르고 수첩 버튼이 튐. 다시 살펴도 말풍선만 나오고 기록·연출은 반복하지 않습니다.
- 수첩 지도는 **관찰한 구역만** 문제 그림·한 줄 메모(예: "입구가 깜깜함")와 해결 미리보기를 보여 줍니다. 관찰 전 구역은 빗금과 "? 조사 전"으로 가려지고, 계획이 그 구역을 해결해도 미리보기를 켜지 않습니다(`FieldRules.PreviewSolved`).
- 주민 말풍선은 한 번에 하나, 한두 줄.

## 수첩 배정 규칙

1. 지도에서 설치 지점을 고른다 → 2. 오른쪽 물품에 체크하면 그 지점에 하나 배정 → 3. 다른 물품을 체크하면 교체, 같은 물품을 다시 누르면 취소.
- 지점당 물품 하나. 같은 물품을 여러 지점에 놓을 수 있고 비용은 지점별로 더합니다.
- 비용은 항상 현재 배정 목록에서 다시 계산합니다(체크 횟수만큼 차감하지 않음).
- 설치할 수 없는 물품은 '이 자리에 설치 불가'와 × 표시, 선택 불가.
- 지도 미리보기: 현재 계획이 해결하는 **관찰한** 문제 구역은 밝은 노랑과 체크. 판정과 같은 데이터(문제 ID 합집합)를 씁니다.
- 확정 조건: 필수 관찰 완료 + 유효 배정 1개 이상 + 예산 이내. 미충족 이유는 아이콘과 짧은 문구(관찰 N곳 남음 / 자리를 골라 체크 / 예산 N 초과). 예산 초과면 게이지가 붉어집니다.
- 정답 판정 문구나 예상 별점은 미리 보여 주지 않습니다.

### 주민 반응 (`FieldMissionData.reactions`)

같은 문제라도 **무엇으로 해결했는지**에 따라 주민 대사와 머무는 자리가 다릅니다. 해결 여부는 판정(FieldRules)이 정하고, 반응 데이터는 보여 주는 방식만 정합니다. 맞는 반응이 없으면 문제의 기본 해결 대사를 씁니다.

| 문제 | 해결한 배치 | 주민 | 대사 |
|---|---|---|---|
| O 바깥 줄 | 대기 줄 옆 그늘막 | 그늘막 기둥 사이, 천막 아래로 걸어가 앉음(바닥 그늘 위) | "이제 햇볕을 피해서 기다릴 수 있겠어요." |
| O 바깥 줄 | 현관 안쪽 대형 냉방기 | 현관 쪽으로 걸어가 바람 앞에 앉음(그늘 없음) | "현관 바람 덕분에 덜 더워요." |
| W 복도 쉼터 | 복도 쉼터 급수장치 | 급수장치 옆으로 가서 물을 마심, 빈 물통은 치움 | "이제 목마를 때 물을 마실 수 있겠어요." |

- 추가 목표를 해결하지 않았다면 주민은 원래 자리에서 불편해합니다.
- 주민이 옮겨 가면 말풍선·클릭 관찰·돋보기 안내·관찰 표시·다시 살펴보기 판정이 모두 새 자리를 기준으로 합니다(`FieldWorld.ObservePoint`, `ResidentPosition`).
- 설치 연출에서는 해당 물품이 놓인 뒤 0.8초 동안 걸어가고, 건너뛰기·즉시 적용은 같은 자리로 바로 정착합니다. 재계획하면 원래 대기 자리로 돌아옵니다.
- 이동 위치는 검증기(`FieldValidator.ResidentFits`)가 건물·벽·다른 설치물과 겹치지 않는지 확인합니다.

### 대사 기준

주민은 자신의 불편이나 해결 뒤 달라진 점을, 담당자는 현장을 살피거나 다음 행동을 말합니다. 물품에 없는 성능(예: 냉각 기능이 없는 급수장치의 '시원한 물')이나 화면에 없는 행동은 말하지 않습니다. 비가 이미 내리는 미션 3은 제목을 "비 내리는 대피소", 도착 대사를 "비가 더 거세지기 전에 서둘러야겠어."로 바꿨습니다.

- 깊이 정렬: 건물·나무·주민·담당자는 발 위치 기준 `SortingGroup` 순서(`100 + (8 - 발Y) × 10`)로 앞뒤가 바뀝니다. 충돌 크기·이동 속도는 바꾸지 않았습니다.
- 담당자: 숨쉬기 대기, 걸을 때 팔다리 흔들기, 좌우 방향, 관찰 자세, 수첩을 드는 자세.
- 설치: 트럭이 와서 서고 물품이 하나씩 놓이며 반짝임. 건너뛰기와 정상 재생은 같은 최종 상태(`ApplyState`)를 한 번만 적용하고, 해결 여부는 규칙 판정 결과만 씁니다.

# v1 카드 비교 버전 (2026-11-04 구현, 보존)

> 공공구매의 가치를 알리기 위한 창작 게임입니다. 실제 계약 절차·평가 방식·제품 성능을 재현하지 않습니다.
> 아래 제품 분류, 수치, 점수식은 모두 게임을 위한 **창작 규칙**이며 실제 법령·조달 심사 기준·제품 인증이 아닙니다.
> 마을·부서·제품은 모두 가상이고, 비용은 원화가 아닌 **게임 단위**입니다.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 카드 선택형 전략 퍼즐 + 마을 변화 연출 |
| 플랫폼 | Windows PC (64비트) 우선. Web 빌드는 만들지 않음 |
| 언어 | 한국어 |
| 목표 플레이 시간 | 첫 플레이 5~8분 (미션 3개, 튜토리얼 포함) |

| 주인공 | 가상의 새봄마을 공공구매 지원팀 신입 담당자 |

## 2. 화면 흐름 (씬 1개, 상태 전환)

타이틀 → (새 게임) → 미션 1 + 튜토리얼 → 결과 → 미션 2 → 결과 → 미션 3 → 결과 → 최종 엔딩

- **타이틀**: 게임 시작(진행 중이면 이어하기 / 처음부터 시작), 게임 방법, 소리 설정, 작품 소개와 출처, 종료. 아래에 문제를 안은 세 시설.
- **마을 지도**: 세 시설 카드. 현재 채택된 결과에 맞춰 시설 모습이 바뀌고, 미션은 차례대로 열린다(부분 해결이어도 다음 미션으로 진행 가능). 해결한 미션은 다시 도전할 수 있다.
- **미션 화면**
  - 상단: 미션명, 예산, 현재 총비용, 납기, 목표 성능, 일시정지
  - 왼쪽: 현재 시설 그림과 주민 요청 말풍선
  - 오른쪽: 물품 A·B 각 3장의 제안 카드 (구매비·유지비·합계·성능·배송일·환경점수와 경고를 hover 없이 항상 표시)
  - 하단: 두 물품 바구니, 총비용 식, 예상 점수, 예상 결과, 구매 확정 버튼과 비활성 이유
- **결과 화면**: 배송 차량 이동 → 물품 도착 → 시설 변화 → 주민 반응 연출(건너뛰기 가능), 이후 성공/부분 해결, 총점과 구성, 비용 구성, 주민 반응, 잘된 선택·아쉬운 선택, 재도전 / 마을 지도 / 다음 미션(마지막은 엔딩 보기)
- **엔딩**: 세 시설의 최종 모습, 세 미션의 결과와 선택 제품, 최종 점수와 최고 기록, 다시 시작 / 마을 지도(재도전) / 타이틀로

## 3. 구매 규칙

- 물품 A와 B에서 각각 하나씩 골라야 구매할 수 있다. 같은 카드를 다시 누르면 선택이 취소된다.
- **구매 확정 버튼 비활성**: 미선택(둘 다·한쪽) 또는 예산 초과. 이유를 버튼 아래에 표시한다.
- **성능 부족·배송 지연**: 카드와 예상 결과에 경고하고, 확정 시 확인창을 한 번 더 보여 주지만 구매는 허용한다.
- 선택 중에는 예산을 차감하지 않는다. 매번 현재 선택만으로 처음부터 다시 계산하므로 변경·취소 시 비용이 누적되지 않는다.
- 확정 시 결과 스냅샷 하나를 만들고 이후 확정 요청(연타 등)은 무시한다.
- 각 미션은 독립 예산이며 남은 예산은 이월하지 않는다.

## 4. 계산식 (`Assets/ProcurementHero/Scripts/Core/Scoring.cs`)

- 총비용 = 두 제품의 구매비 합계 + 유지비 합계 (유지비는 평가 기간 전체 비용, 반복 차감 없음)
- 납기계수 = 배송일수 ≤ 미션 납기이면 1, 아니면 0.4
- 성과점수 = 두 제품의 (성능 / 100 × 납기계수) 평균 × 60
- 환경점수 = 두 제품 환경점수 평균 / 100 × 15
- 예산점수 = Clamp01((예산 − 총비용) / 예산) × 25
- 총점 = 성과점수 + 환경점수 + 예산점수
- 계산 중 반올림하지 않고 표시할 때만 소수점 첫째 자리로 반올림한다.
- 구매 전 예상 점수와 결과 화면은 같은 함수 `Scoring.Evaluate`를 쓴다.

**미션 성공** = 총비용 ≤ 예산 **그리고** 두 제품 모두 목표 성능 이상 **그리고** 두 제품 모두 납기 준수.
성공 여부와 총점은 따로 표시한다. 예산을 아꼈지만 요청을 해결하지 못하면 "예산은 아꼈지만 요청을 모두 해결하지는 못했어요."라고 알려 준다.
제품 상세 열람이나 튜토리얼 진행 같은 단순 행동에는 점수를 주지 않는다.

**최종 점수** = 현재 채택된 세 미션 점수의 합계. 재도전은 해당 미션 결과를 대체한다(중복 가산 없음).

**엔딩**
| 성공 미션 수 | 엔딩 |
|---|---|
| 3 | 모두의 하루를 바꾼 조달 히어로 |
| 2 | 성장하는 공공구매 해결사 |
| 0~1 | 다시 도전하는 마을 지원팀 |

## 6. 연출

모든 그림은 기본 도형(사각형·둥근 사각형·원·삼각형·빛 번짐)을 실행 시 코드로 만든 Sprite로 그린다 (`ShapeSprites.cs`, `FacilityView.cs`).

| 시설 | 구매 전 | 물품 A 변화 | 물품 B 변화 |
|---|---|---|---|
| 학교 | 어두운 강당, 주민 표정 "…" | 조명이 켜지고 축제 깃발이 나타남 | 스피커에서 음표가 떠오름 |
| 보건소 | 큰 해와 아지랑이, 붉은 얼굴 | 에어컨과 시원한 바람, 더위 표현 감소, 벤치에 앉아 쉼 | 급수대가 생기고 주민이 급수대로 이동 |
| 대피소 | 비구름·빗줄기, 높은 물 | 비상등이 깜박이고 창문이 밝아짐 | 배수 펌프가 작동하고 물 높이가 내려감 |

- 물품별 수준: 0 없음 · 1 부분 개선(성능 부족 또는 지연) · 2 완전 해결. 부분 개선은 조명 일부만 켜짐, 음표가 드묾, 더위가 절반만 줄어듦, 물이 절반만 빠짐처럼 완전 성공과 다르게 보인다.
- 주민 반응: 완전 해결 ★과 통통 튀기, 부분 해결 ○, 미해결 "…", 말풍선 문구(성공/부분/실패).
- 건너뛰기(버튼 또는 Space): 즉시 최종 상태를 적용한다. 결과는 구매 확정 시점에 이미 저장되므로 건너뛰어도 게임 상태는 같다.
- 일시정지: `Time.timeScale = 0`으로 연출을 멈춘다. 메뉴 버튼과 효과음은 계속 동작한다.

## 7. 튜토리얼과 안내

미션 1에서 처음 한 번만, 실제 화면 위에 짧은 배너와 강조 테두리로 진행한다(건너뛰기 가능, 점수 영향 없음).
① 요청 확인 → ② 제안 비교 → ③ 두 물품 선택(두 물품을 고르면 자동 진행) → ④ 비용 확인 → ⑤ 구매(구매 확정 시 종료)

행동 직후 짧은 안내(한 번씩):
- 처음 제품을 고를 때: "가격뿐 아니라 성능, 유지비, 필요한 시점을 함께 살펴봐요."
- 납기를 넘기는 제품을 고를 때: "필요한 때 도착해야 물품의 가치가 현장에서 이어져요."
- 혁신형 제품을 고를 때: "새로운 제품을 현장에서 사용하고 성능을 확인하는 과정도 중요해요."

## 8. 색과 상태 표시

- 배경 크림(#FFF6E3), 본문 남색(#1F2A4D), 강조 청록(#139E9A)
- 상태는 색과 기호·문구를 함께 쓴다: 성공 "○ 성공"(초록), 부분 해결·경고 "△"(주황), 차단·초과 "×"(빨강), 선택 "○ 선택됨"(청록 배경)
- 키보드 포커스는 남색 테두리로 표시

## 9. 저장

- PlayerPrefs에 최고 기록(최고 점수·최다 성공 수)과 소리 설정(효과음·배경음 볼륨, 음소거)만 저장. 개인정보 없음.
- 미션 진행은 실행 중에만 유지. "처음부터 시작"은 진행이 있으면 확인창을 띄운 뒤 초기화.
- 최고 기록 초기화는 소리 설정 창의 별도 버튼(확인창 포함).
