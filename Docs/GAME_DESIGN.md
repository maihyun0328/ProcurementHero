# 조달 히어로 — 게임 기획 (구현 기준)

> 공공구매의 가치를 알리기 위한 창작 게임입니다. 실제 계약 절차·평가 방식·제품 성능·조달청 업무를 재현하지 않습니다.
> 물품, 비용, 효과, 별 평가는 모두 게임을 위한 **창작 규칙**입니다.

이 문서에는 두 버전이 있습니다.

- **v2 현장 수첩 버전 (현재 시작 씬)**: 아래 「v2」 절. 원문 기획서는 `Docs/v2/ProcurementHero_Game_Design_v2.md`.
- **v1 카드 비교 버전 (보존)**: 아래 「v1」 절. 씬과 데이터는 그대로 남아 있습니다.

# v2 현장 수첩 버전 (2026-11-06 구현)

씬 `Assets/ProcurementHero/Scenes/FieldNotebook.unity` · 데이터 `Assets/ProcurementHero/Data/Field/` · 규칙 `Scripts/Core/Field/FieldRules.cs`

## 흐름

타이틀 → 현장 도착(소개 배너) → 탐색과 관찰 → 수첩 계획 → 계획 확정 → 배송과 설치 → 현장 재확인 → 별 평가 → 다음 현장 → 엔딩

| 상태 | 받는 입력 | 비고 |
|---|---|---|
| 탐색 | 이동(WASD·방향키), 관찰(E·Enter·돋보기 클릭), 수첩(Tab·수첩 버튼), 일시정지(Esc) | 현장 HUD 버튼은 키보드 선택을 갖지 않음(Enter가 관찰과 겹치지 않게) |
| 수첩 | 방향키·WASD로 항목 이동, Enter 실행, Tab·Esc 닫기 | 현장 이동과 연출 정지, 계획·선택 지점 유지 |
| 설치 | Space·버튼으로 건너뛰기, Esc 일시정지 | 건너뛰어도 같은 최종 상태를 한 번만 적용 |
| 재확인 | 이동·관찰 | 문제였던 곳 한 곳을 살펴보면 '결과 보기' 버튼 |
| 결과·엔딩 | UI 버튼 | |

- 상태가 바뀐 프레임에는 현장 입력을 받지 않아, 한 번 누른 키가 두 동작을 일으키지 않습니다.
- 일시정지는 `Time.timeScale = 0`, 닫으면 1로 복구. 일시정지 위에 설정 창을 겹쳐 열고 닫아도 정지가 남지 않습니다.

## 관찰

- 관찰 범위 2.2 안에서 가장 가까운 대상 하나만 고릅니다. 멀리서 클릭하면 "더 가까이 가야 살펴볼 수 있어요".
- 관찰하면 수첩에 문제 그림이 기록되고 현장에 체크 표시가 남습니다. 다시 살펴도 기록·보상은 늘지 않습니다.
- 주민 말풍선은 한 번에 하나, 한두 줄.

## 수첩 배정 규칙

1. 지도에서 설치 지점을 고른다 → 2. 오른쪽 물품에 체크하면 그 지점에 하나 배정 → 3. 다른 물품을 체크하면 교체, 같은 물품을 다시 누르면 취소.
- 지점당 물품 하나. 같은 물품을 여러 지점에 놓을 수 있고 비용은 지점별로 더합니다.
- 비용은 항상 현재 배정 목록에서 다시 계산합니다(체크 횟수만큼 차감하지 않음).
- 설치할 수 없는 물품은 '이 자리에 설치 불가'와 × 표시, 선택 불가.
- 지도 미리보기: 현재 계획이 해결하는 문제 구역은 밝은 노랑과 체크. 판정과 같은 데이터(문제 ID 합집합)를 씁니다.
- 확정 조건: 필수 관찰 완료 + 유효 배정 1개 이상 + 예산 이내. 미충족 이유는 아이콘과 짧은 문구(관찰 N곳 남음 / 자리를 골라 체크 / 예산 N 초과). 예산 초과면 게이지가 붉어집니다.
- 정답 판정 문구나 예상 별점은 미리 보여 주지 않습니다.

## 별 평가

| 별 | 조건 |
|---|---|
| 3 | 필수 문제 전부 + 추가 목표 전부 |
| 2 | 필수 문제 전부 |
| 1 | 필수 문제 일부 |
| 0 | 필수 문제 해결 없음 |

성공은 별 2개 이상. 성공해야 다음 현장이 열립니다. 별 0개여도 결과 화면까지 진행되고 '다시 계획하기'로 이어집니다.
재계획: 현장을 설치 전으로 되돌리고, 관찰 기록은 보존, 이전 계획을 수정 가능, 이전 결과에서 남은 구역은 지도에서 빨간 테두리. 새 확정 결과가 그 현장의 결과를 대체합니다(누적 없음).

기록: 현장별 최고 별 `PH2_Field_BestStars_<미션ID>`, 별 합계 `PH2_Field_BestTotalStars`. v1 점수 키(`PH_BestScore` 등)와 섞지 않고, 현장 기록 초기화는 v1 기록을 지우지 않습니다.

엔딩: 별 합계 9 "모두의 하루를 바꾼 조달 히어로", 7~8 "꼼꼼한 현장 해결사", 그 외 "성장하는 현장 지원 담당자"(엔딩 칭호는 개발 중 정한 문구).

## 현장 표현

모두 기본 도형 Sprite를 코드로 만든 임시 그림입니다(`FieldArt.cs`, `FieldWorld.cs`). 물품 그림은 `FieldItemVisual` 키별로 한 곳에 모여 있어 나중에 그림만 바꿀 수 있습니다.

| 문제 | 해결 전 | 해결 후 |
|---|---|---|
| 어둠 | 구역 위 어두운 막, 멈춘 주민 | 막이 걷히고 빛 번짐, 주민이 오가며 ★ |
| 더위 | 주황 막과 움직이는 아지랑이 | 푸른 막, 아지랑이 사라짐 |
| 물 부족 | 빈 물통 | 물통이 참 |
| 전원 | 꺼진 창문, 깜빡이는 비상등 | 창문 점등, 비상등 초록 |
| 침수 | 파란 물 막과 물결 | 물이 거의 빠짐 |

충돌: 건물·벽·울타리·물웅덩이·나무는 그림과 같은 사각형 `BoxCollider2D`. 플레이어는 `Rigidbody2D` + `CircleCollider2D`(반지름 0.35), 속도 6, 대각선 정규화. 카메라 고정(정사영 크기 9).

# v1 카드 비교 버전 (2026-11-04 구현, 보존)

> 공공구매의 가치를 알리기 위한 창작 게임입니다. 실제 계약 절차·평가 방식·제품 성능을 재현하지 않습니다.
> 아래 제품 분류, 수치, 점수식은 모두 게임을 위한 **창작 규칙**이며 실제 법령·조달 심사 기준·제품 인증이 아닙니다.
> 마을·부서·제품은 모두 가상이고, 비용은 원화가 아닌 **게임 단위**입니다.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 카드 선택형 전략 퍼즐 + 마을 변화 연출 |
| 플랫폼 | Windows PC (64비트) 우선. Web 빌드는 만들지 않음 |
| 언어 | 한국어 |
| 목표 플레이 시간 | 첫 플레이 5~8분 (미션 3개, 튜토리얼 포함) |
| 조작 | 마우스 클릭 중심, 키보드 보조 (방향키 · Enter · Esc · Space) |
| 주인공 | 가상의 새봄마을 공공구매 지원팀 신입 담당자 |

## 2. 화면 흐름 (씬 1개, 상태 전환)

타이틀 → (새 게임) → 미션 1 + 튜토리얼 → 결과 → 미션 2 → 결과 → 미션 3 → 결과 → 최종 엔딩

- **타이틀**: 게임 시작(진행 중이면 이어하기 / 처음부터 시작), 게임 방법, 소리 설정, 작품 소개와 출처, 종료. 아래에 문제를 안은 세 시설.
- **마을 지도**: 세 시설 카드. 현재 채택된 결과에 맞춰 시설 모습이 바뀌고, 미션은 차례대로 열린다(부분 해결이어도 다음 미션으로 진행 가능). 해결한 미션은 다시 도전할 수 있다.
- **미션 화면**
  - 상단: 미션명, 예산, 현재 총비용, 납기, 목표 성능, 일시정지
  - 왼쪽: 현재 시설 그림과 주민 요청 말풍선
  - 오른쪽: 물품 A·B 각 3장의 제안 카드 (구매비·유지비·합계·성능·배송일·환경점수와 경고를 hover 없이 항상 표시)
  - 하단: 두 물품 바구니, 총비용 식, 예상 점수, 예상 결과, 구매 확정 버튼과 비활성 이유
- **결과 화면**: 배송 차량 이동 → 물품 도착 → 시설 변화 → 주민 반응 연출(건너뛰기 가능), 이후 성공/부분 해결, 총점과 구성, 비용 구성, 주민 반응, 잘된 선택·아쉬운 선택, 재도전 / 마을 지도 / 다음 미션(마지막은 엔딩 보기)
- **엔딩**: 세 시설의 최종 모습, 세 미션의 결과와 선택 제품, 최종 점수와 최고 기록, 다시 시작 / 마을 지도(재도전) / 타이틀로

## 3. 구매 규칙

- 물품 A와 B에서 각각 하나씩 골라야 구매할 수 있다. 같은 카드를 다시 누르면 선택이 취소된다.
- **구매 확정 버튼 비활성**: 미선택(둘 다·한쪽) 또는 예산 초과. 이유를 버튼 아래에 표시한다.
- **성능 부족·배송 지연**: 카드와 예상 결과에 경고하고, 확정 시 확인창을 한 번 더 보여 주지만 구매는 허용한다.
- 선택 중에는 예산을 차감하지 않는다. 매번 현재 선택만으로 처음부터 다시 계산하므로 변경·취소 시 비용이 누적되지 않는다.
- 확정 시 결과 스냅샷 하나를 만들고 이후 확정 요청(연타 등)은 무시한다.
- 각 미션은 독립 예산이며 남은 예산은 이월하지 않는다.

## 4. 계산식 (`Assets/ProcurementHero/Scripts/Core/Scoring.cs`)

- 총비용 = 두 제품의 구매비 합계 + 유지비 합계 (유지비는 평가 기간 전체 비용, 반복 차감 없음)
- 납기계수 = 배송일수 ≤ 미션 납기이면 1, 아니면 0.4
- 성과점수 = 두 제품의 (성능 / 100 × 납기계수) 평균 × 60
- 환경점수 = 두 제품 환경점수 평균 / 100 × 15
- 예산점수 = Clamp01((예산 − 총비용) / 예산) × 25
- 총점 = 성과점수 + 환경점수 + 예산점수
- 계산 중 반올림하지 않고 표시할 때만 소수점 첫째 자리로 반올림한다.
- 구매 전 예상 점수와 결과 화면은 같은 함수 `Scoring.Evaluate`를 쓴다.

**미션 성공** = 총비용 ≤ 예산 **그리고** 두 제품 모두 목표 성능 이상 **그리고** 두 제품 모두 납기 준수.
성공 여부와 총점은 따로 표시한다. 예산을 아꼈지만 요청을 해결하지 못하면 "예산은 아꼈지만 요청을 모두 해결하지는 못했어요."라고 알려 준다.
제품 상세 열람이나 튜토리얼 진행 같은 단순 행동에는 점수를 주지 않는다.

**최종 점수** = 현재 채택된 세 미션 점수의 합계. 재도전은 해당 미션 결과를 대체한다(중복 가산 없음).

**엔딩**
| 성공 미션 수 | 엔딩 |
|---|---|
| 3 | 모두의 하루를 바꾼 조달 히어로 |
| 2 | 성장하는 공공구매 해결사 |
| 0~1 | 다시 도전하는 마을 지원팀 |

## 6. 연출

모든 그림은 기본 도형(사각형·둥근 사각형·원·삼각형·빛 번짐)을 실행 시 코드로 만든 Sprite로 그린다 (`ShapeSprites.cs`, `FacilityView.cs`).

| 시설 | 구매 전 | 물품 A 변화 | 물품 B 변화 |
|---|---|---|---|
| 학교 | 어두운 강당, 주민 표정 "…" | 조명이 켜지고 축제 깃발이 나타남 | 스피커에서 음표가 떠오름 |
| 보건소 | 큰 해와 아지랑이, 붉은 얼굴 | 에어컨과 시원한 바람, 더위 표현 감소, 벤치에 앉아 쉼 | 급수대가 생기고 주민이 급수대로 이동 |
| 대피소 | 비구름·빗줄기, 높은 물 | 비상등이 깜박이고 창문이 밝아짐 | 배수 펌프가 작동하고 물 높이가 내려감 |

- 물품별 수준: 0 없음 · 1 부분 개선(성능 부족 또는 지연) · 2 완전 해결. 부분 개선은 조명 일부만 켜짐, 음표가 드묾, 더위가 절반만 줄어듦, 물이 절반만 빠짐처럼 완전 성공과 다르게 보인다.
- 주민 반응: 완전 해결 ★과 통통 튀기, 부분 해결 ○, 미해결 "…", 말풍선 문구(성공/부분/실패).
- 건너뛰기(버튼 또는 Space): 즉시 최종 상태를 적용한다. 결과는 구매 확정 시점에 이미 저장되므로 건너뛰어도 게임 상태는 같다.
- 일시정지: `Time.timeScale = 0`으로 연출을 멈춘다. 메뉴 버튼과 효과음은 계속 동작한다.

## 7. 튜토리얼과 안내

미션 1에서 처음 한 번만, 실제 화면 위에 짧은 배너와 강조 테두리로 진행한다(건너뛰기 가능, 점수 영향 없음).
① 요청 확인 → ② 제안 비교 → ③ 두 물품 선택(두 물품을 고르면 자동 진행) → ④ 비용 확인 → ⑤ 구매(구매 확정 시 종료)

행동 직후 짧은 안내(한 번씩):
- 처음 제품을 고를 때: "가격뿐 아니라 성능, 유지비, 필요한 시점을 함께 살펴봐요."
- 납기를 넘기는 제품을 고를 때: "필요한 때 도착해야 물품의 가치가 현장에서 이어져요."
- 혁신형 제품을 고를 때: "새로운 제품을 현장에서 사용하고 성능을 확인하는 과정도 중요해요."

## 9. 저장

- PlayerPrefs에 최고 기록(최고 점수·최다 성공 수)과 소리 설정(효과음·배경음 볼륨, 음소거)만 저장. 개인정보 없음.
- 미션 진행은 실행 중에만 유지. "처음부터 시작"은 진행이 있으면 확인창을 띄운 뒤 초기화.
- 최고 기록 초기화는 소리 설정 창의 별도 버튼(확인창 포함).
